# J3160 / Debian 13 部署 Halo + CellBridge

此配置使用 Linux amd64 构建。集成分支是 `integration/vocat-cellbridge`，SIP 和大疆音频默认关闭。当前只完成软件测试，尚未在 NAS 或电话硬件上验证。本文中的 Docker 命令需要 NAS 已安装 Docker Engine 和 Compose 插件。

## Docker 部署

在 NAS 上检出或解压集成源码，进入项目根目录。使用 `compose.nas.yml`，它构建本项目的 Halo 集成镜像。仓库原来的 `docker-compose.yml` 默认拉取上游 VoCat 镜像，不包含此次融合代码。

```sh
mkdir -p nas-data qdc507-runtime
docker compose -f compose.nas.yml build
```

首次使用空数据库时，初始化管理员。密码只在 NAS 终端输入，经标准输入传给程序，管理员凭据保存在 SQLite 中：

```bash
read -rsp 'Halo 管理员密码: ' HALO_SETUP_PASSWORD
printf '\n'
printf '%s\n' "$HALO_SETUP_PASSWORD" | docker compose -f compose.nas.yml run --rm -T \
  --entrypoint /opt/vocat/bin/vocat halo bootstrap-admin
unset HALO_SETUP_PASSWORD
```

已有 Halo 数据应先停止原实例并备份整个数据目录，再将该目录配置为 `nas-data` 挂载源；已有管理员的数据库跳过初始化。备份用于回退，因为本分支包含数据库迁移。避免多个实例同时访问相同设备或数据文件。

```sh
docker compose -f compose.nas.yml up -d
docker compose -f compose.nas.yml logs --tail=100 halo
curl --fail http://127.0.0.1:7575/healthz
```

浏览器访问 `http://NAS地址:7575` 完成设备设置。浏览器语音需要 HTTPS；SIP 客户端通话不要求浏览器麦克风权限。停止服务使用 `docker compose -f compose.nas.yml down`，这条命令保留本机 `nas-data` 数据目录。

## 硬件检查

容器镜像包含 `arecord`、`aplay`、`adb`、`pcscd` 和 CCID 驱动。配置使用主机网络以及 `/dev`、`/sys` 挂载，支持实际 USB 设备与声卡发现。宿主机 Linux 仍须识别模块及其 USB 声卡；镜像内安装 ALSA 工具不能替宿主机补齐内核驱动。

```sh
docker compose -f compose.nas.yml exec halo sh -c 'uname -m; command -v adb; command -v arecord; command -v aplay; command -v pcscd'
docker compose -f compose.nas.yml exec halo arecord -l
docker compose -f compose.nas.yml exec halo aplay -l
```

大疆 QDC507 的三个外部厂商文件放到主机 `qdc507-runtime` 目录，容器内运行时目录填写 `/opt/halo/qdc507`。文件、哈希、匹配的模块内核与声卡要求见 [CellBridge 通话桥](CellBridge.zh-CN.md)。软件不会自动获取厂商文件。首先确认模块和声卡就绪，再按实际设备开启大疆音频与启动引导。

SIM 读卡器通过 PC/SC 完成 SIM 认证，通话走已注册的 IMS；仅发现 USB 读卡器不等于 IMS 已就绪。宿主机若已有 `pcscd` 或其他程序持有读卡器，先解决设备占用再验证容器中的读卡器路径。

## iPhone 远程通话

先在局域网完成双向通话和录音验证，再把 iPhone 通过 WireGuard 等可达 VPN 接入 NAS。电话页分别设置 SIP 线路与大疆音频设备；读卡器 IMS 线路无需开启大疆音频。

SIP 默认 UDP `5060`，RTP 默认 UDP `40000`；对外地址填 iPhone 实际能访问的 NAS 局域网或 VPN 地址。HTTPS 网页反向代理只覆盖网页入口，不能自动代转 SIP/RTP UDP。

在 iPhone 的 SIP 客户端填写该地址、端口及电话页的账号密码。当前没有实现 iOS 原生 App 或推送唤醒；锁屏和后台来电需要结合所用 SIP 客户端验证。远程拨号、本地通话、锁屏来电和延迟都需要实际测试。

## 预编译 amd64 程序

如果拿到带 `halo-linux-amd64` 的部署包，可直接在 Debian 13 使用这份程序，网页资源已嵌入其中。二进制通过 `CGO_ENABLED=0 GOARCH=amd64 GOAMD64=v1` 构建，使用 J3160 的基础指令集。运行原生程序时仍需宿主机提供 ALSA、ADB、PC/SC 及相关驱动：

```sh
sudo apt-get update
sudo apt-get install alsa-utils adb pcscd libccid ca-certificates iproute2
./halo-linux-amd64 version
```

原生程序的部署包布局包含 `halo-linux-amd64` 和 `source/` 源码目录。在解压目录运行以下命令可安装原生服务：

```sh
sudo install -d -m 0755 /opt/halo/bin /opt/halo/data /opt/halo/qdc507
sudo install -m 0755 halo-linux-amd64 /opt/halo/bin/halo
sudo install -m 0644 source/deploy/halo-cellbridge.service /etc/systemd/system/halo-cellbridge.service
```

空数据库初始化管理员（已有数据库跳过），然后启动服务：

```bash
read -rsp 'Halo 管理员密码: ' HALO_SETUP_PASSWORD
printf '\n'
printf '%s\n' "$HALO_SETUP_PASSWORD" | sudo /opt/halo/bin/halo bootstrap-admin --database /opt/halo/data/halo.db
unset HALO_SETUP_PASSWORD
sudo systemctl daemon-reload
sudo systemctl enable --now halo-cellbridge.service
sudo systemctl status halo-cellbridge.service --no-pager
```

这里使用原生服务专用的 `/opt/halo/data/halo.db`。大疆厂商文件放在 `/opt/halo/qdc507`，电话页填写同一路径。既有 Halo 部署先按前文完成停机与备份，再决定数据目录。原生程序和 Docker 是两种部署方式，应选定一种；本包不自动修改 NAS 上现有服务。J3160 能运行 amd64 程序不代表已经完成 USB 驱动、IMS 注册或延迟验收。

依赖包名核对：[Debian 13 ALSA 工具](https://packages.debian.org/trixie/alsa-utils)、[ADB](https://packages.debian.org/trixie/adb)、[CCID 驱动](https://packages.debian.org/trixie/libccid)。Docker 内使用 Alpine 的 [alsa-utils](https://pkgs.alpinelinux.org/package/v3.20/main/x86_64/alsa-utils) 和 [android-tools](https://pkgs.alpinelinux.org/package/v3.20/community/x86_64/android-tools)。
